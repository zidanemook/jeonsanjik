# 문제 하나 = 카드 하나 (영어) — v57

## 무엇이 문제였나

과목 화면이 `312문항 · 풀 문제 62개`처럼 보였다. 앞의 수는 **문항**(문장)을, 뒤의 수는 **카드**(복습 일정 단위)를 셌는데, 한국어로 "문항"과 "문제"는 같은 말이라 같은 단위로 읽힌다. 영어 규칙 카드 하나가 여러 문장을 돌려 냈기 때문에 두 수가 크게 어긋났고, 평소 모드로는 대부분의 문장에 닿을 수 없었다.

측정해 보니 여러 문장을 돌려 내는 카드는 **영어에만** 있었다.

| 범위 | v56 | v57 |
|---|---|---|
| Day 1 (`grammar-verb-*`) | 카드 12 → 129문항 | **60문제 = 카드 60** |
| 수일치 | 카드 20 → 95문항 | **95문제 = 카드 95** |
| 그 밖의 문법(영문법) | 카드 20 → 60문항 | **60문제 = 카드 60** |

한국사·국어·컴퓨터일반·정보보호론의 모든 카드(자체 제작·한능검·9급 기출)는 이미 카드 하나가 문제 하나였다. 이번에 그 카드들은 한 글자도 바뀌지 않았다(검토 지문 4,847개 그대로).

## 바꾼 것

### 1. Day 1 → 준비된 60문제

- 규칙 카드 12개(`grammar-verb-*`, 129문항)를 지우고, 검토를 마친 `research/english-days/day1-60.json`의 **60문제**(4지선다 40 · 직접 쓰기 20)를 `en-day1-01`~`en-day1-60`으로 넣었다.
- 문장·보기·정답 번호·허용 답안·해설은 **원고 그대로**다. 통합 뒤 60문제 전부를 원고와 필드 단위로 대조했다.
- 해설 화면의 "규칙과 비교 예문"은 이전 Day 1 규칙 카드 12개의 정리(title·rule·hook·examples)를 그대로 쓴다. 문제마다 속한 규칙(`ruleId`, 예: `grammar-verb-preposition`)과 문법 포인트(`point`, 24개)를 적었다.
- 사용자 규칙인 **Day당 자체 제작 60문제**와 같다.

### 2. 수일치·그 밖의 문법 → 한 문장씩

- 규칙의 **4지선다**(`quiz-options.js`)는 **원래 카드 id**를 그대로 쓴다. 이 파일은 바꾸지 않았다.
- `practice-bank.js`에 규칙별로 적혀 있던 연습 문장은 적힌 순서대로 **`<규칙 id>-v1`, `-v2` …** 문제가 된다. 문장·정답·해설은 원본과 같은 객체이며, 원본 은행과 문장 단위로 대조했다(115문장).
- 나뉜 문제는 모두 **원래 규칙 정리를 함께 들고 있어** 해설 화면이 규칙을 그대로 가르친다.
- 원본 문장은 `practice-bank.js`에 규칙별로 모아 둔 채 두고, 파일 끝의 한 단계가 이를 문제 하나씩으로 편다. 그래서 규칙에 문장을 하나 더 적으면 새 `-vN` 문제가 되고, 검토 지문 대장이 그 추가를 잡는다.

### 3. 틀리면 같은 규칙의 다른 문제가 이어서 나온다

규칙 카드가 주던 학습 효과(한 규칙을 여러 문장으로 되풀이)는 `review-policy.js`의 **개념 묶음**으로 옮겼다. 오늘 틀린 문제가 있으면 같은 개념의 다른 문제를 일정과 상관없이 불러와 형제 간격(10분) 뒤에 낸다(`app.js`의 `reviewQueue`, 기존 동작).

- `<규칙 id>-vN` → 원래 규칙의 개념. 원래 규칙이 다른 규칙과 묶여 있었다면 그 묶음을 따른다(예: `grammar-agreement-both-v1` → `grammar-agreement-identity`, `…-while-short-v2` → `grammar-while-during`).
- Day 1 → **문법 포인트 하나가 개념 하나**(`grammar-day1-<포인트>`, 24개). 이전의 Day 1 카드 짝 묶음 4개(`grammar-verb-transitivity` 등)는 카드가 없어져 지웠다.
- 목록은 `BEGIN/END ENGLISH ONE-QUESTION GROUPS` 블록에 문제 id마다 적었다(175개). `content-audit.cjs`의 `concepts()`가 `ruleId`·`point`와 어긋나지 않는지 검사한다.

평소 모드에서 Day 1을 처음 열면, 포인트마다 한 문제씩 24문제를 풀고 나서 같은 포인트의 나머지 36문제가 10분 뒤에 이어서 나온다. 기다리지 않고 전부 풀려면 **이 범위 전부 풀기**를 켠다(60문제).

### 4. 다시 들어오지 못하게

`content-audit.cjs`가 **모든 카드가 정확히 한 문제를 낸다**는 것을 원본을 읽을 때(`catalog()`)와 목록 단위(`single()`)에서 강제한다.

대조 실험: `grammar-agreement-each-v1`에 두 번째 문장을 임시로 넣고 `node content-audit.cjs`를 돌리면 `Every card must yield exactly one question (no multi-question bundles): grammar-agreement-each-v1 yields 2`로 **실패(exit 1)**했고, 되돌리면 통과했다.

### 5. 화면의 수와 말

화면에 보이는 모든 수를 **"문제" 한 단위**로 센다. 문제 하나가 곧 카드 하나이므로 두 수는 같은 단위다.

| 곳 | v56 | v57 |
|---|---|---|
| 첫 화면 과목 줄 | `312문항 · 풀 문제 62개` | `전체 N문제 · 지금 풀 차례 M문제` |
| 과목 화면 요약(`#subjectSummary`) | `…문항 · 풀 문제 …개 (새 문제 k개 포함) · 오늘 푼 문제 x개` | `전체 N문제 · 지금 풀 차례 M문제 (새 문제 k개 포함) · 오늘 푼 문제 x개` |
| 범위 줄 | `n문제 · 첫 시도 a/n · 정답 c · 풀 문제 m · 새 문제 k` | `전체 N문제 · 첫 시도 a/N · 정답 c · 지금 풀 차례 M문제 (새 문제 k개 포함)` |
| 기출 연도 접기 | `첫 시도 a/n` | `첫 시도 a/n문제` |
| 진행상황 | `풀 문제 · 복습 카드 · 오늘 푼 문제` | `지금 풀 차례 · 전체 문제 · 오늘 푼 문제` |
| 대기 안내 | `n개 관련 카드 · …부터` | `같은 개념의 문제 n개 · …부터` |
| 막힌 화면 드릴 버튼 | `이 범위 전부 풀기 · n문항 · …` | `… · n문제 · …` |
| 드릴 완료 · 회차 완료 · 한능검 회차 점수 · 수정 안내 | `문항` | `문제` |

- "오늘 푼 문제"는 이제 **그날 푼 서로 다른 문제 수**다(같은 문제를 드릴로 여러 번 풀어도 하나). 풀이 횟수는 학습량 환산 시간에 따로 나온다.
- "지금 풀 차례"는 지금 실제로 낼 수 있는 문제 수다(재시도 대기·형제 간격으로 쉬는 문제는 빠진다).
- `drill.js`의 진행 문구도 `…문제를 모두 맞혔어요`로 바꿨다.
- 바꾸지 않은 "문항": 한능검·9급 기출 해설 머리말(`hanneung.js`·`gichul.js`의 "이 문항은 공식 문제와…")과 `core-review-pack.js`의 출처 문구(“…자체 제작 문항”)는 문제 본문·해설의 일부라, 바꾸면 한국사·국어 등의 검토 지문이 전부 바뀐다. 이번 범위에서 뺐다.

## 풀이 기록 — 끊기는 곳

**기록은 한 건도 지우지 않았다.** `history`의 각 풀이는 당시의 문제·보기·내 답·정답·해설 스냅숏(`detail`)이라 그대로 남고 그대로 동기화된다. 카드 일정(`data.cards`)도 지우지 않는다.

- **Day 1 규칙 카드 12개**: 더는 풀 수 있는 문제가 아니라 화면·수에서 빠진다. 카드 항목과 기록은 저장소에 그대로 있다. 새 60문제는 새 카드(오늘 due)라 첫 풀이부터 시작한다.
- **수일치·그 밖의 문법의 4지선다**: 카드 id도 문제 식별자(`exerciseId` = 카드 id + 문제·정답 지문)도 **그대로**라 기록·일정이 이어진다. 다만 그 카드의 일정은 v56까지 여러 문장의 풀이로 쌓인 것인데, 이제는 4지선다 하나에만 적용된다.
- **나뉜 연습 문장(`-vN`)**: 새 카드(오늘 due)이고 문제 식별자가 바뀌었다(`<규칙 id>-vN-<지문>`). 그래서 이 문장들의 v56 기록(`<규칙 id>-<지문>`)은 **살아 있는 문제와 짝이 맞지 않는다**. 첫 풀이·반복 분류(`ReviewPolicy.classify`)에서 새 식별자는 첫 풀이로 센다.
- 문장 수정 안내(`content-corrections.js`)는 저장된 스냅숏의 식별자로 찾으므로 옛 기록에는 계속 붙는다.
- 업데이트 순간 없어진 카드의 채점 화면·풀던 문제가 열려 있었다면 앱을 열 때 그 **화면 상태만** 비운다. 그대로 두면 채점 화면이 남아 다음 답을 받지 못한다.
- 영향받는 기록은 영어 연습을 시작한 며칠치다.

## 수치

- 전체 검토 지문 5,131 → **5,062** (영어 −129 +60). 영어 자체 제작 연습 **215문제** + 논지 복습 1.
- 검토 지문 대장(`content-review.json`): 영어 연습 항목만 새로 기록했다(4지선다 40개 재기록 · 175개 추가 · 244개 삭제). 그 밖의 4,847개는 한 글자도 바뀌지 않았고, 갱신 스크립트가 영어가 아닌 지문이 하나라도 달라지면 멈추게 했다.
- 보기 길이 편향: 정답이 유일하게 가장 긴 비율 **105/497(21.1%) → 105/501(21.0%)**, 래칫 21.2%는 그대로. 지운 Day 1 4지선다 36개와 새 40개 모두 그런 문항이 0개다. 평균 초과폭 +1.77 → +1.78자.
- 설치 묶음 `core-2026-09-12-v23`, 자산 `?v=57`, 캐시 `chagog-v57-english-one-question-each`.

## 검사 변경

- `content-audit.cjs` — 카드당 한 문제 불변식(`catalog()`·`single()`), 개념 일관성(`concepts()`). 영어 범위 검사는 **카드 단위 → 규칙 단위**: 규칙마다 4지선다 1개 이상, 직접 쓰기 `englishWrittenFloor` 이상(수일치·영문법 **2** — v56과 같은 기준, Day 1 **1**), 한 규칙의 직접 쓰기 문장은 모두 서로 달라야 한다(v56은 "서로 다른 것 2개 이상"). `grammar-agreement-identity`의 인원 문맥 검사는 그 규칙의 모든 문제에 그대로 건다.
- `content-coverage.json` — `englishWrittenFloor` 추가, `requiredRules` 값의 뜻을 카드 id → 규칙 id로 적었다(이름은 그대로).
- `practice.test.cjs` — "항목마다 변형 2개 이상·다시 풀면 다른 문장" → "항목마다 정확히 한 문제·다시 풀면 같은 문제, 객관식은 정답 번호만 이동". 나뉜 문제가 규칙 정리를 그대로 들고 있는지, 범위별 수(60/95/60, Day 1은 40+20·포인트 24)를 새로 검사. 채점 검사는 옮겨 간 문장(`-v1`/`-v2`)을 가리키게 했다.
- `review-policy.test.cjs` — 범위 검사 대조군을 규칙 단위로 바꾸고, 수일치 직접 쓰기 2개 하한·Day 1 하한 대조군, 카드당 한 문제 대조군, 개념 일관성 대조군 2개, **실제 `reviewQueue`로 "틀리면 같은 규칙의 나머지 6문제가 10분 뒤 이어서 나온다"**(개념 묶음을 뺀 대조군에서는 틀린 문제 하나만 돌아온다)를 더했다.
