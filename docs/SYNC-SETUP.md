# 학습 진행 동기화 연결

2026-09-09 Firebase 프로젝트 `jeonsanjik-study`에 연결했습니다. Spark 플랜, Standard Firestore의 서울 리전(`asia-northeast3`), Google 로그인, 본인 UID 허용 목록을 사용합니다. GitHub Pages 도메인 `zidanemook.github.io`를 승인했습니다. Analytics와 Gemini는 프로젝트 생성 시 활성화하지 않았습니다.

## 연결 순서

1. 소유자의 Firebase 콘솔에서 Spark 프로젝트를 만들거나 기존 프로젝트를 선택합니다. Analytics와 유료 플랜은 필요하지 않습니다.
2. 웹 앱을 등록하고 공개 웹 설정(apiKey, authDomain, projectId, appId)을 로컬 `firebase-config.js`에 넣습니다. 이 파일은 `.gitignore`로 제외합니다. 같은 설정 JSON을 GitHub Actions Secret `STUDY_FIREBASE_CONFIG`에 보관하면 배포 작업이 런타임 파일을 생성합니다. 서비스 계정 키나 비밀번호를 넣지 않습니다.
3. Authentication에서 Google 로그인을 활성화하고 `zidanemook.github.io`를 승인 도메인에 추가합니다.
4. Cloud Firestore를 만들고 저장소의 `firestore.rules`를 게시합니다. 테스트 모드의 공개 접근 규칙을 사용하지 않습니다.
5. 소유자가 앱에서 처음 로그인하면 Authentication에 UID가 생성됩니다. 콘솔에서 `allowedUsers/{그 UID}` 문서를 생성합니다. 이 문서는 관리자만 생성할 수 있습니다. 다른 계정은 학습 기록 읽기와 쓰기가 모두 거부됩니다.
6. 설정을 배포하고 소유자의 두 기기에서 같은 Google 계정으로 로그인합니다. 첫 로그인 때 해당 기기에 있던 기존 기록을 자동 이관합니다.

## 동작

- 각 풀이에 고유 ID를 부여하고 서버에는 변경할 수 없는 이벤트로 저장합니다. 동일 ID 재전송은 중복 채점하지 않습니다.
- v16부터 이벤트의 선택적 `detail`에 실제 예문·보기·내 답·정답·해설·예문/개념 ID를 함께 저장합니다. 길이와 필드를 제한하고 기존의 소유자 인증·변경 금지를 유지합니다. 신규 필드를 허용하는 `firestore.rules`를 앱 배포 전에 게시해야 합니다. 과거 상세 정보 없는 이벤트도 계속 읽을 수 있습니다.
- 같은 이벤트를 구버전이 상세 정보 없이 저장한 사본과 병합할 때는 원래 상세 정보를 보존합니다. 상세 답안 자체가 충돌하면 덮어쓰지 않고 오류로 처리합니다.
- 실시간 구독으로 다른 기기의 풀이를 받고 기록 합집합에서 다음 복습일을 다시 계산합니다. 같은 날 중복 정답으로 간격이 늘어나지 않습니다.
- 오프라인 풀이는 브라우저에 남습니다. 네트워크 복구 또는 정기 재시도 때 전송합니다. 앱을 닫은 동안에는 전송되지 않으며 다음 실행 때 이어집니다.
- 오답 후 같은 날 정답을 맞히면 다음 날 다시 복습합니다. 같은 날 여러 오답의 간격 패널티는 한 번만 적용합니다.
- 문제와 보기 콘텐츠는 GitHub 배포로 공급합니다. 계정별 학습 기록과 현재 기기의 해설 화면은 분리합니다.
- 최초 이관 뒤에는 계정별 저장 영역을 사용합니다. 로그아웃하거나 계정을 바꿔도 다른 계정에 이전 계정의 기록을 올리지 않습니다.
- 이벤트 순서는 기록된 날짜·시각·ID로 결정됩니다. 단말기의 날짜가 잘못 설정된 상황까지 서버 시각으로 보정하지는 않습니다.

## 검증 범위

`sync-core.test.cjs`: 기기별 기록 합치기 순서 독립성, 중복 제거, 같은 날 충돌, 재시도 일정.

`sync.test.cjs`: 모의 서버를 이용한 두 클라이언트 실시간 전달, 오프라인 동시 풀이, 재전송, 계정 분리. 실제 Firebase 테스트를 대신하지 않습니다.

실제 서버 검증 완료: 서로 독립된 Edge 컨텍스트에서 동일 계정으로 로그인한 상태의 온라인 기록 전달, 양쪽 오프라인 동시 풀이 세 건 합집합, 재연결 후 일정 일치, 동일 이벤트 재전송 중복 없음. 타 사용자 경로 읽기·기존 이벤트 변조·삭제 및 미인증 SDK 읽기는 모두 `permission-denied`였습니다. 검증용 이벤트 세 건은 이후 관리자 콘솔에서 삭제했습니다. 이는 실제 Android 태블릿을 직접 조작한 테스트는 아닙니다.

v16 상세 답안 검증: 실제 사용자 이벤트 경로와 분리한 임시 검증 경로에 동일한 생성 검증 규칙을 적용했습니다. 두 독립 Edge 컨텍스트에서 앱의 채점 결과(예문·보기·내 답·정답·해설)가 Firebase를 거쳐 일치하는 것을 확인했습니다. 답안 변조, 허용하지 않은 필드, 타 사용자 접근은 거부됐습니다. 검증 기록은 삭제했고 임시 경로 권한도 제거했습니다. 기존 사용자 학습 기록에 검증용 풀이를 넣지 않았습니다.

공식 문서: [웹 설정](https://firebase.google.com/docs/web/setup), [Google 로그인](https://firebase.google.com/docs/auth/web/google-signin), [실시간 구독](https://firebase.google.com/docs/firestore/query-data/listen), [보안 규칙](https://firebase.google.com/docs/firestore/security/rules-conditions). 2026-09-09 Edge에서 확인했습니다. 웹 SDK는 공식 배포 파일 12.2.1을 vendor에 고정했습니다.

## 공개 키 탐지 알림 대응

GitHub에서 Firebase 브라우저 키를 Google API Key로 탐지했습니다. Firebase 웹 API 키는 프로젝트 식별용 공개 설정이며, 비공개 서버 자격 증명이 아닙니다. 최신 소스에서는 실제 설정을 제외하고 Actions 빌드에서 생성하도록 변경했습니다. 이전 커밋의 문자열이나 배포된 웹 설정이 비밀로 바뀌는 것은 아닙니다. 과거 커밋은 재작성하지 않았습니다.

필요한 API는 Cloud Firestore API, Identity Toolkit API, Token Service API입니다. 허용 웹사이트는 `https://zidanemook.github.io/*`와 로그인 처리용 `https://jeonsanjik-study.firebaseapp.com/*`입니다. 웹사이트 제한은 로그인·Firestore 보안 규칙을 대체하지 않습니다. [Firebase 공식 API 키 보안 안내](https://firebase.google.com/docs/projects/api-keys)를 따릅니다.


## 학습량 환산 시간 (v20)

- 채점한 풀이 1회는 +1분, 해당 풀이의 학습 내용을 처음 펼치면 +1분입니다. 정답·오답·보조 풀이 및 객관식·직접 쓰기를 같은 기준으로 인정합니다. 실제 집중 시간이나 경과 시간을 측정한 수치는 아닙니다.
- 가산 대상은 채점 후의 규칙·비교 예문과 기록 화면의 풀었던 문제·내 답입니다. 같은 풀이 ID에 묶어서 두 위치를 모두 열거나 닫았다 다시 열어도 해설 가산은 한 번입니다. 키보드로 펼쳐도 같습니다. 과목 선택·성적·기록 목록·날짜별 시간 같은 탐색 영역은 가산하지 않습니다.
- 풀이 가산은 기존 mode: quiz 이벤트를 사용합니다. 해설 기록은 별도 explanationViews 배열과 Firestore users/{uid}/explanationViews/{풀이 ID}에 id·openedAt만 저장합니다. 풀이 점수·답안·복습 일정은 수정하지 않습니다.
- 풀이 시간은 풀이 기록 날짜에, 해설 가산은 처음 펼친 날(한국 시간)에 표시합니다. 기존 풀이도 소급 환산하지만 기록하지 않았던 과거 해설 열기는 추정하지 않습니다. 이전 자기평가 등 문제풀이 여부가 불분명한 기록은 제외합니다.
- 오프라인에서는 두 기록 모두 로컬에 저장하고 재연결 시 풀이 이벤트를 먼저, 해설 기록을 다음에 보냅니다. 같은 풀이를 두 기기에서 동시에 펼쳤다면 가장 이른 열기 시각으로 합쳐 한 번만 가산합니다. 해설은 보안 규칙의 문서 조회 한도를 고려해 최대 10개씩 전송합니다.
- Firebase는 허용된 본인의 실제 quiz 이벤트에 연결된 해설 기록만 허용합니다. 열기 시각은 최초 기록보다 이른 값으로만 병합할 수 있고 삭제는 금지합니다. 기존 퀴즈 불변 기록 규칙을 유지합니다.

## 이어풀기 위치 (v28)

- 계정마다 문서 하나 `users/{uid}/state/session`에 현재 연습 범위(과목·주제·회차)와 풀던 문제(카드 ID·예문 ID·변형 번호·보기 순서)를 저장합니다. 채점 기록과 달리 덮어쓰는 문서입니다.
- 위치는 사용자의 명시적 동작(범위 선택, 채점, 다음 문제)에서만 갱신합니다. 화면을 다시 그리거나 다른 기기의 기록을 받는 것만으로는 바뀌지 않습니다.
- `at`이 더 큰 쪽이 이깁니다. 새 값은 `max(현재 시각, 마지막으로 본 위치+1)`이라 기기 시계가 늦어도 뒤이은 동작이 앞선 위치를 이깁니다. 보안 규칙은 저장된 값보다 `at`이 작거나 같은 쓰기를 거부하고 삭제를 막습니다.
- 다른 기기의 더 새로운 위치를 받으면 같은 범위를 열고, 해당 문제를 같은 보기 순서로 복원합니다. 콘텐츠가 바뀌어 같은 예문을 찾지 못하면 범위만 적용합니다. 채점 결과 화면 상태는 공유하지 않습니다.
- 위치 구독·저장이 실패해도(규칙 미게시 등) 풀이 기록 동기화는 그대로 진행합니다.
- 검증: `sync-session.test.cjs`(모의 서버: 전달, 늦은 시계, 오프라인 충돌, 규칙 미게시 시 기록 전송 유지), Edge UI 검증 `tools/verify_steps_ui_20260911.cjs`(Firebase 없이 병합·이어하기).
