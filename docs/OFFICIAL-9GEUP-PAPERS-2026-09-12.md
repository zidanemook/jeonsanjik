## 2. 수록 원칙

1. **문제·보기·정답은 원문 그대로.** 다듬거나 현대화하지 않는다. 보기는 원문 ①②③④ 번호를 글자에 그대로 달고 순서를 섞지 않는다(`fixedOrder`).
2. **정답은 공식 정답표의 값만 쓴다.** `docs/gichul-answer-keys.json`은 정답표 PDF에서 기계로 뽑은 행이고, `hanneung.test.cjs`가 58문항을 하나씩 대조한다. 앱이 정답을 다시 판단하지 않는다.
3. **그림·도식·표 배치가 자료인 문항은 싣지 않는다.** 대신 사유를 `gichul-data.js`의 `skipped`에 남긴다.
   - 자료(제시문)가 2차원 표·도식이면 제외한다.
   - 보기만 (가)·(나) 같은 짧은 낱말 열이면 한 줄로 펴서 수록한다(정보 손실이 없다). 그 경우 `transcription`에 사유를 적는다.
4. **해설은 자체 작성이다.** 출제기관의 글이 아니다. `정답 근거:` / `보기 비교:` / `기억 연결:` 3단. 확신이 없으면 해설 없이 공식 정답만 낸다.

### 제외한 문항

| 회차 | 문항 | 사유 |
|---|---|---|
| 2026 지방직 9급 컴퓨터일반 | 16번 | 프로세스·도착 시간·실행 시간 **3열 표**가 문제의 자료(FCFS 평균 반환 시간). 표 배치를 텍스트로 재현할 수 없다. |
| 2026 지방직 9급 정보보호론 | 3번 | 구분·메시지 인증 코드·전자서명 **3열 표**와 (가)~(라) 4열 보기표. 자료 자체가 2차원 격자다. |

2026 지방직 9급 한국사는 그림·표 문항이 없어 20문항 전부 수록했다.

### 전사 충실도 대조

`gichul-data.js`의 문제·보기 문자열 **290개 가운데 285개**가 공식 PDF의 `pdftotext -layout` 추출본에 공백 정규화 기준으로 **글자 단위로 그대로** 들어 있다. 나머지 5개는 다음과 같고, 원문 인쇄면(PDF 렌더 이미지)을 직접 보고 맞췄다.

- 컴퓨터일반 6번 ① `O(n²)` — 수식 글꼴이라 추출에서 사설영역(PUA) 문자로 떨어진다.
- 컴퓨터일반 13번 ①~④ — (가)·(나) 2열 보기표를 `① (가) exec()  (나) 0` 형태로 폈다.

추출기가 **지워 버린 낫표**도 인쇄면을 보고 되살렸다(추출본에는 없거나 U+F000으로 나온다):
`『경국대전』`(한국사 8), `『성학집요』`(한국사 9②), `「서당」·「씨름」`(한국사 10), `『경세유표』·『(가)』`(한국사 11), `「조선 혁명 선언」`(한국사 18), `「개인정보 보호법」`(정보보호론 17·18·19).

## 3. 과목·범위 구조

- 카드 id는 `gichul-<회차 id>-<두 자리 문항 번호>`. 예: `gichul-local9-2026-computer-01`.
- 범위 값은 `paper-<회차 id>`. 과목을 가리지 않으므로 새 과목이 생겨도 분기를 늘리지 않는다.
- 화면: **과목 → 기출 · 회차별 → `2026 지방직 9급`**. 한능검 `기출 · 회차별 심화`와 같은 자리 구조이고, 한국사에는 `기출 · 공무원 9급` 묶음이 하나 더 붙는다.
- 새 과목 컴퓨터일반·정보보호론은 카드에서 과목 목록이 만들어지므로 과목 화면에 저절로 나온다.

## 4. 회차는 앱이 문제를 고르지 않는다

`sequentialScope()`가 참인 범위(공무원 기출 한 회차 · 한능검 n회)에서는 **1번 → 마지막 번호까지 원문 순서 그대로** 내고 끝나면 멈춘다. 켜야 하는 모드가 아니라 회차의 기본 동작이다.

- 복습 일정 필터 없음 — 어제(또는 방금) 맞힌 문제도 제자리에 다시 나온다.
- 5분 재시도 대기(`retryAt`) 없음, 형제 개념 간격(`ReviewPolicy.separate`) 없음, 하루 새 문제 몫(`NEW_CARDS_PER_DAY`) 없음.
- 보기 순서를 섞지 않는다.
- **기록은 평소와 똑같다.** 채점 결과·복습 일정·환산 시간·약점 분석 모두 그대로 남는다. 바뀌는 것은 "다음에 무엇을 낼지"뿐이다.
- 같은 날 회차를 여러 바퀴 돌아도 복습 간격이 부풀지 않는다 — 드릴이 쓰던 `StudyDrill.assess` 래퍼를 그대로 쓴다(두 번째 래퍼를 만들지 않았다).
- 위치는 저장하지 않는 세션 값이라 **회차를 다시 열면 언제나 1번부터** 시작한다.
- 회차 안에서는 `이 범위 전부 풀기`(드릴) 버튼을 감춘다. 회차가 이미 전부 풀기이므로 두 방식이 부딪힐 자리를 없앴다. 드릴은 회차가 아닌 범위에서 그대로 동작한다.
- 한능검 회차 점수(첫 시도 공식 배점)는 계산 방식이 그대로다(`Hanneung.stats`).

## 5. 검사

- `content-audit.cjs`: 공식 기출은 원문을 늘일 수 없으므로 **보기 길이 편향 측정에서 제외**한다. 기준은 id 접두사 하나뿐이다 — `VERBATIM_OFFICIAL=/^(?:hanneung|gichul)-/`. 자체 제작 문항 실측치는 추가 전후 모두 **105/497(21.1%)**로 같고 래칫 0.212도 그대로다. 대신 공식 기출에는 `fixedOrder`와 보기 번호(①~④) 검사를 새로 걸었다.
- `hanneung.test.cjs`: 회차별 공식 정답표 대조, 수록+제외 = 원문 20문항, 문항 번호 순서·중복, 4지선다, 보기 번호, 출처 줄, 반복 풀이 시 보기 순서 고정, 그리고 길이 편향 면제가 접두사에 걸려 있는지.
- `drill-app.test.cjs`: 회차가 게이트 없이 순서대로 전부 나오는지, 다시 열면 1번부터인지, 같은 날 두 바퀴가 간격을 부풀리지 않는지, 한능검 79회도 같은지, 회차 점수가 그대로인지, 회차가 아닌 범위는 예전 그대로인지.

## 6. 확인하지 못한 것

1. **해설의 정확성**은 자동 검사로 증명되지 않는다. 58개 해설은 1차 작성자(이 세션) 검토뿐이고 독립 검토를 받지 않았다.
2. 공식 정답이 틀렸다고 볼 만한 문항은 발견하지 못했다. 58문항 모두 문제 내용과 공식 정답이 일치했다.
3. 2025 지방직·2010 국가직은 **공식 정답표가 디스크에 없어** 손대지 않았다. 재구성 정답은 쓰지 않는다.
4. 국어·영어(지방직·국가직 2026)는 라이선스·정답표 조건을 모두 만족하지만 이번에 수록하지 않았다. 장문 지문 전사량이 커서 한 회차를 온전히 끝내지 못할 위험이 있었고, 반쯤 전사한 회차는 손대지 않은 회차보다 나쁘다.
5. 문항 안의 제3자 저작물 여부를 전수 점검하지는 않았다. 수록한 세 과목은 코드·표·용어·역사 사료가 중심이라 구조적으로 노출이 낮다(한국사 사료는 보호기간이 지난 원사료 인용이다).
6. 코드 문항의 `\n`은 한국어 글꼴에서 원화 기호(₩)로 그려진다. 데이터는 역슬래시가 맞고, 한국어 윈도 환경의 글꼴 관례다.
