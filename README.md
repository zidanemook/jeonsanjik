# 차곡 — 전산직 문제 복습 앱

차곡은 전산직 학습을 위한 개인용 복습 웹앱입니다. 객관식과 짧은 답 입력으로 문제를 풀고, 채점과 해설을 확인한 뒤 다음 문제로 넘어갑니다.

화면의 문제는 공개 자료를 바탕으로 학습용으로 다시 구성한 연습 문제입니다. 원문 기출 문항이나 공식 정답지를 그대로 제공하는 서비스가 아니며, 문제의 출처와 성격은 카드의 해설에서 확인할 수 있습니다.

## 사용 방법

1. 과목을 고릅니다. 영어에서는 수일치만 따로 연습할 수 있습니다.
2. 선택지를 누르거나, 문제에서 지정한 단어·구절만 입력하고 채점합니다.
3. 답을 낸 뒤 채점과 설명을 확인합니다. 필요하면 규칙과 비교 예문을 더 펼쳐 봅니다.
4. 채점과 설명을 확인하고 다음 문제로 넘어갑니다. 틀린 카드는 5분 뒤와 다음 날 다시 풀며, 변형 예문이 있는 카드는 다른 예문이 차례로 나옵니다.
5. 학습 기록에서 날짜·정오답과 함께 실제 풀었던 예문·보기·내 답·정답·해설을 펼쳐 볼 수 있습니다. 이전 버전에서 수집하지 않은 상세 답안은 추측해서 복원하지 않습니다.

기존 35개 카드와 추가 수일치 카드 6개가 있습니다. 23개 문법 카드에 직접 쓰기 예문 52개가 준비되어 있습니다. 객관식 35문항을 포함해 총 87개 예문을 사용합니다. 객관식 선택지 순서를 바꾸되 정답도 함께 추적합니다.

## 예문별 기록과 출제

- 예문 내용과 정답으로 식별자를 만들고 제출 때의 내용을 보존합니다. 이후 문제를 고쳐도 과거 기록의 문장·답은 변하지 않습니다.
- ‘처음 푼 예문’과 ‘다시 푼 예문’을 따로 집계합니다. 같은 규칙을 10분 안에 풀거나 설명을 보고 푼 결과는 ‘이어서 연습’으로 별도 집계합니다. 상세 기록이 없던 과거 풀이 때문에 첫 풀이 여부를 알 수 없으면 신규 성적으로 계산하지 않습니다.
- 이 지표는 기록상 예문을 처음 풀었는지 구분하는 것이며 실제로 처음 본 문장인지, 시험 전이가 입증됐는지, 완전히 숙달했는지를 판정하지 않습니다. 복습 일정은 카드 단위로 관리합니다.
- 별도 카드라도 같은 규칙으로 등록된 형제 카드는 마지막 관련 풀이로부터 10분 뒤에 출제합니다. 다른 규칙의 문제는 계속 풀 수 있습니다. 같은 카드의 오답 재시도는 기존 5분 규칙을 유지하고 ‘이어서 연습’으로 구분합니다. 10분은 제품 정책이며 검증된 최적 간격이 아닙니다.
- 형제 묶음은 `review-policy.js`의 명시적 목록으로 관리합니다. 현재 while/during, of whom, 능동·수동, 중심 주어 관련 카드를 묶었습니다. 범위가 비슷하다는 이유로 모든 수일치 규칙을 한 그룹으로 묶지는 않습니다.

직접 쓰기는 자유 영작이 아닙니다. 지정한 단어나 빈칸의 짧은 답을 미리 검토한 정답 목록과 비교합니다. 대소문자, 여분 공백, 끝의 마침표와 등록된 축약형·대체 정답을 허용합니다. LLM API나 추가 과금은 없습니다. 보기만 찍어 맞힌 답과 근거를 알고 맞힌 답은 별도로 판별하지 않습니다.

각 기기에서 같은 Google 계정으로 로그인하면 풀이 기록과 다음 복습일이 자동 동기화됩니다. 허용된 본인 계정만 사용할 수 있습니다. 첫 로그인 시 기존 기기의 기록도 합쳐집니다. 로그인 전에는 해당 브라우저에만 저장됩니다.

인터넷이 끊겨도 학습할 수 있고, 앱이 열린 상태에서 다시 연결되면 기록을 전송합니다. 화면의 `학습 기록 동기화됨` 표시로 서버 반영을 확인할 수 있습니다. 관리자 설정과 검증 범위는 [동기화 설정](docs/SYNC-SETUP.md)을 참고하세요.

입력 중인 답과 현재 화면은 해당 기기에 보관합니다. 제출한 정오답·실제 예문·내 답·정답·해설과 다음 복습일은 기기 간 동기화합니다. 승인된 본인 계정만 접근합니다. 오프라인에서 서로 다른 기기가 같은 예문이나 형제 카드를 풀 수 있지만, 재연결 후 합쳐진 기록으로 간격과 성적을 다시 계산합니다. 연결이 끊긴 두 기기의 출제를 실시간으로 서로 막지는 못합니다.

## 문제 추가와 검토

`content-audit.cjs`는 정답 누락, 중복 보기, 허용 답안의 채점, 동일인 예문의 인원 문맥 등 구조를 검사합니다. `content-review.json`에는 수동 검토한 콘텐츠의 해시가 있습니다. 문제·보기·정답·해설·규칙 설명이 바뀌면 기존 해시와 달라져 배포 검사가 실패합니다.

추가·수정 시 사람이 문맥, 복수 정답 가능성, 허용 표현을 확인한 뒤 검토 해시를 갱신합니다. 해시는 검토 뒤의 변경을 잡는 장치이며, 문법·사실의 정확성을 자동으로 증명하지 않습니다. 검토 해시를 자동 재생성하는 작업은 배포 과정에 넣지 않습니다. 정답이 여러 개로 성립하는 주관식은 모두 등록하거나 문제의 조건을 구체화합니다.

2026-09-09에는 87문항과 문법 설명 23묶음을 적대적으로 검토하여 인칭 누락, 복수 정답 누락, 모호한 예문 등을 수정했습니다. [검토 결과와 근거](docs/CONTENT-REVIEW-2026-09-09.md). 수정 전 풀이를 열면 `content-corrections.js`에 등록된 현재 해설이 함께 표시됩니다. 당시 답안과 채점은 보존하며, 과거 점수를 소급하여 바꾸지는 않습니다.

## 실행

로컬에서는 `firebase-config.example.js`를 `firebase-config.js`로 복사한 뒤 본인 프로젝트의 웹 설정을 넣습니다. 실제 설정 파일은 Git에서 제외됩니다. GitHub 배포는 Actions Secret `STUDY_FIREBASE_CONFIG`의 JSON으로 설정 파일을 생성합니다. 웹 앱에 전달된 Firebase 설정은 브라우저에서 볼 수 있으며, 서버 접근 제어는 인증과 보안 규칙이 담당합니다.

~~~text
python -m http.server 8766 --bind 127.0.0.1
~~~

PC에서 <http://localhost:8766>을 엽니다. 설치와 오프라인 기능은 HTTPS 또는 localhost에서 동작합니다.
